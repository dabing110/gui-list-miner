# 微信 PC 端 · 三个列表视图的实测参数

环境：微信 PC 4.1.x，Windows 系统缩放 125%，窗口最大化后
`GetWindowRect = (-9, -9, 1929, 1039)`（1938×1048 物理像素）。

> 窗口被最小化时 `GetWindowRect` 返回 `(-25600,-25600)` 且不出现在 `list_windows()`；
> 用 `restore(hwnd)` 还原后矩形与上次一致，坐标参数不用改。

## 通用准备

1. 微信窗口 hwnd 拿到后固定不变（本次全程 1051982）。
2. 进程要 `SetProcessDpiAwareness(2)`，否则 125% 缩放下坐标全错。
3. 鼠标悬停点：列表区中部，避开左侧导航和右侧滚动条 → `--rel-x 0.93 --rel-y 0.5`。

---

## ① 公众号点赞

**入口**：微信主窗 → 左侧「公众号」 → 右上角个人中心 → 「赞和收藏」 → 切到「赞」标签。

| 参数 | 值 |
|---|---|
| 裁剪 BOX | `(1535, 180, 1938, 1048)` |
| 滚动 | `--scroll -2` |
| 行结构 | 标题行高 ≥15，来源号名 <15，条目间隙 >42px |
| 数据量 | 455 帧 → 1353 原始 → 去重后 **1186 条**，跨度约 6 年 |

**时间范围推断法**：没有时间戳字段，找一篇你知道发布日期的文章
（如阮一峰《科技爱好者周刊》某期），按它在列表里的行号反推近一年的截止位置。

---

## ② 最近阅读（「转发给我」的替代品）

微信**没有转发日志**。用户想找「别人转发给我的内容」时，用最近阅读做替代。

**入口**：公众号 → 个人中心 → 「最近阅读」。

| 参数 | 值 |
|---|---|
| 裁剪 BOX | `(1060, 140, 1938, 1048)` ← 与点赞不同 |
| 滚动 | `--scroll -2` |
| 解析 | linear 模式，`--x-min 10` |

**⚠️ 数据边界**：列表末尾有 UI 提示「**只保留最近1个月的浏览记录**」。
所以最近阅读只有约 1 个月数据（实测 620 条），与跨度数年的点赞清单重合很少是
数据本身特性，不是去重失效 —— 别误判成 bug 反复调阈值。

**踩坑**：`--x-min` 若沿用旧裁剪线的 55，会误杀行首字（标题起点 X=34），
导致标题普遍丢开头 2 字（「岁前，给你7点建议」）。裁剪左=1060 时正确值是 **10**。

**日期分隔行**：`今天 / 昨天 / 前天 / 星期X / N月N日`，用 DATE_RE 单独排除，
不要当成条目。UI 文本「清空阅读记录」要拉黑。

## ③ 视频号「赞」

**入口**：微信主窗 → 左侧「视频号」 → 右上角个人中心 → 「赞和收藏」。
默认打开是「全部」视图，顶部有筛选条 `全部 / ♡ / 👤 / ⭐`，
**点 ♡ 图标才切到「赞」**（物理坐标约 `1312, 154`，点击后等 1.5s 再截屏确认）。

| 参数 | 值 |
|---|---|
| 裁剪 BOX | `(1050, 140, 1938, 1048)` |
| 滚动 | `--scroll -1`（120px，小于半行周期 176px，安全） |
| 布局 | 3 列卡片，标题行起点局部 x ≈ **187 / 410 / 632** |
| 列范围 | `(150,405) (405,620) (620,890)` |
| 行周期 | `PERIOD = 352`，`PHASE_TOL = 9` |
| 字高 | 标题 H ≥ 15.0，作者 H ≤ 14.5 |
| 标题→作者 | `dy ∈ [22, 36]`，实际固定 +28 |
| 列对齐容忍 | `X_ALIGN = 22`（首字漏识时 x0 右移约 17px 是常态） |
| 数据量 | 694 帧 → 3905 对 → 去重后 **629 条** |

**卡片结构实测**：标题**只有 1 行**（超长截断），下方 +28px 是作者名。
封面内的字幕、时长角标「00:48」（OCR 常误识成「〔48」）、点赞数「1.6万」
（👍 常被误识成「凸」）相位随机 → 靠网格相位过滤掉。

**作者行噪声规则**（`author_like()`）：
- 无时长 `\d{1,2}:\d{2}`、不以 `〔[【〖（` 开头、不含「凸」
- 阿拉伯数字 ≤1 个、长度 ≤16、至少含一个汉字或字母（挡掉纯符号「·」）

**去重阈值**：Jaccard 0.9 不够，最终用
`标题 SequenceMatcher ≥ 0.78 且 作者 ≥ 0.6`
（例：「禪让制究竟…」vs「禪让制宄見…」ratio 仅 0.818，双字误识靠这条合并）。

## 已确认的数据边界

| 视图 | 覆盖范围 | 与其他视图重合 |
|---|---|---|
| 公众号点赞 | 约 6 年，1186 条 | — |
| 最近阅读 | 仅最近 1 个月，620 条 | 与点赞重合 47 |
| 视频号赞 | 未标注时间，629 条 | 与公众号侧零重合 |

**PC 端拿不到的**：企业微信内的转发/点赞（需在职账号）、
「别人转发给我的」精确记录（无此日志）→ 这两项只能手机侧人工补采。
